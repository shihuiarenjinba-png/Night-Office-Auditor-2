## 現状と守ること
- 現行24件本編 (`index.html`) は、まだ順番に進む固定構造。**分岐版として発売可とは扱わない。**
- `branch-case04.html` は独立した操作可能な一事件プロトタイプ。低価格版と本編24件のセーブを変更しない。
- **事実の真相はルートによって変わらない。** ルートで変えるのは「接触人物・協力・情報入手経路・進める順番・代償・次に開く事件・最後に立証できる範囲」。
- 記録にない犯人・動機・資金移動・同一人物の断定を、劇的なセリフのために足さない。

## CASE 04 の中心的対立
- 島袋 颯（現場主任）：明日朝の公演を止めたくない。強硬な調査には反発、丁寧な聞取りには発注番号を提示。
- 仲村 澪（経理）：帳簿は確認したいが、責任を一人で被せられることを恐れている。安全を約束すると原本にアクセスを許す。名指しを迫ると文書請求へ移行。
- 金城 玲子（承認権限者）：署名したかという証言と、代理権限が有効かは別だと理解する人物。本人の署名ログ・規程に到達した場合に登場。
- **事件の確定真相：** 42万円発注はPO-044、電子承認ID EVT-044、発注23分前の変更されていない署名ログ、代理承認規程3条と署名が一致。正当な承認。
- **誤った判断のリスク：** 早期告発→現場と経理の協力低下、正式文書請求の時間増、訂正要請。正しい結論の早当てでも証拠不足なら監査品質は低評価。

## 1事件の分岐実装（今回）
```
CASE 04 / 白紙の承認欄
  ├ 現場から聞く
  │   ├ 尊重して発注番号を確認 → 経理に接続
  │   └ 決めつけて責める → 経理の情報アクセスに障害
  ├ 経理を保護して聞く
  │   ├ 原本と承認IDを得る → ログ照合
  │   └ 名指しを迫る → 文書請求に時間と関係コスト
  └ 先に無断発注と告発
      ├ 撤回して正式照会 → 関係修復の代償を伴い続行
      └ そのまま報告 → 誤告発の責任を負う

ログを検証した場合のみ代理権限を照合する導線へ
  ├ 規程・電子署名・台帳・時刻を照合 → 裏付けある「問題なし」
  ├ 結論は一致したが資料を省略 → 裏付け不足
  ├ 再調査 → 正式な保留（設営側に実務上の影響）
  └ 証拠に反して告発 → 関係悪化・報告訂正
```

## 本編全体を非線形化するために必要な追加実装
この部分は未実装。今後のStoryGraph/Save schema設計で扱う。

1. `unlockedCaseIds`, `completedCaseIds` と `routeFlags` を持つStoryGraph。ケースIDで参照し、`index + 1` だけで次話を固定しない。
2. 事件ごとに「共通の事実」、3つ以上の人物の事情、「選択で得られる情報」、「証拠の提示タイミング」、「道筋の違う結末」、「次の案件への影響」を個別に台本化。
3. 第1章は「経理との協力」「現場との衝突」「文書照会ルート」へ。分岐によって第2章で受け取る相談先・事件の解禁順・説明者を変える。
4. **重要な証拠は永久に取り逃がさない設計にする。** 関係が悪ければ正式照会・別の記録照合による高コストの代替経路を用意し、推理はプレイヤーが証拠で納得できるようにする。
5. 終盤は「権限を使って隠蔽を立証したが協力網を失う」「協力者と手続きを守りながら立証する」「証拠が足りず断定を避けて継続調査」のように、**立証範囲と人的関係の両軸**を描く。犯罪の有無そのものをプレイヤーの選択で書き換えない。
6. 既存24件の証拠台帳を維持した上で、分岐ごとに独自の人物会話、真の情報差、必要なサブ案件を追加する。共通文の言い換えだけを別ルートと数えない。
7. 各ルートの自動QA：全選択肢の到達性、行き止まりなし、根拠未確認で人物特定不可、全エンディングの到達性、セーブ再開、旧セーブの非破壊、タブ表示、Windows UIを検証。

## 完成判定
「24案件」「3つの選択肢」があるだけでは有料版完成ではない。
**選択により台詞・人物関係・資料の入手経路・後続の調査と結末が実際に変わり、全分岐で証拠が筋道を持っていること**を認定条件とする。
