# 深夜監査室 有料版 — 事件別「証拠カード上限」設計

対象：有料拡張版。低価格版（NightOfficeAuditor）のゲームロジックとStore情報は変更しない。
作業ブランチ：`work/case04-card-budget-20261024`。本編の24件へは未導入。初回は CASE 04 の独立したブラウザ試作で操作性を検証する。

## CASE 04で実装したルール

- 事件の冒頭に解決すべき3つの疑問を提示する。
- 証拠カードは**毎回固定8枚**。カード名・資料種別・文書IDは開封前から読めるが、本文は開封後のみ。
- **開けるのは最大6枚**。1枚開くと残り枠が1減る。裏面に戻らず内容も保存される。
- 証拠の組み合わせ（関連付け）は上限なし。間違っても開封枠・証拠・評価を失わない。
- 3つの疑問それぞれに独立した2枚の証拠が必要で、合計で6枚。正しい6枚を選べば必ず解決できる。解答をランダムに入れ替えない。
- 余分の2枚は「現場主任のメール」「納品チェック票」で、話の背景を理解できる一方、正式承認の立証には使えない。後で開示される根拠と混同しない。
- 6枠のうち何枚かを補助資料に使うと3件すべては立証できなくなる。その場合でも**追加調査として報告できる**。重要な事件進行を閉塞させない。
- 「問題なし」「問題あり」という断定は3つの疑問すべてに根拠がそろった場合にのみ提出できる。人物の罪を選択だけで創作しない。
- セーブキーは `night-office-case04-card-budget:v2`。前の無制限試作・本編24件・低価格版の保存データに触れない。
- 一度の誤った関連付けに罰則を与えない。「調査枠の使い方」だけを戦略的資源とする。
- ヒントは任意の補助であり、カードの内容そのものは自動公開しない。カードの種類と質問の対応を示す。

## CASE 04の解明条件

| 疑問 | つなぐ証拠 | 結論 |
| --- | --- | --- |
| 紙の署名欄以外に承認記録は存在するか | 紙の発注書 + 電子発注台帳 | PO-044 と EVT-044 が紐づく |
| 承認は正式発注より前で後付けでないか | 発注登録ログ + 電子承認ログ | 20:48 の発注に対し20:25の承認で、23分前 |
| 承認者の権限は有効か | 代理承認規程 + 承認者の電子署名 | 社内規程第3条と金城玲子の署名が対応 |

資料と真相を直接紐づけているため、根拠なしの「実はこの人が改ざんした」などは起こさない。

## 残り23案件へ横展開する際の審査項目

事件ごとに、最低限次の値を事前に決め、テストする。

```javascript
{
  caseId: "case-specific-id",
  objective: "プレイヤーが解決すべき中心的疑問",
  cardCount: 8,             // 事件ごとに固定
  revealLimit: 6,           // 事件ごとに固定・表示必須
  questions: [ /* 事件の証拠と対応した疑問 */ ],
  cards: [ /* 文書ID・タイトル・事前表示するカテゴリ・本文 */ ],
  proofPairs: [ /* 具体的な資料IDと、そこから論理的に導ける結論 */ ],
  contextCards: [ /* 必須ではないが事件の雰囲気と人物の立場を知る資料 */ ],
  incompleteEnding: "正式照会・追加調査として進める分岐"
}
```

一律8枚に決め打ちするのではなく、事件の複雑さに応じて増減させる。ただし**解明に必要な最小のカード数が開封上限以下であること**、プレイヤーが資料名から絞り込めること、開封できなかった時も報告が成立することを全件で検証する。
